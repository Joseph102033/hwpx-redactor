# HWPX 공개본 자동 변환기 (Cowork 없이 로컬 실행)

## ⭐⭐⭐ 파이썬 없는 PC용 배포판 (2026-10-22)

`배포판/HWPX_Redactor/` 폴더를 통째로 복사 → `HWPX_Redactor.exe` 에 파일 끌어놓기 또는 더블클릭(폴더 감시).
- **.hwp 도 입력 가능**: PC에 설치된 한글로 자동 .hwpx 변환 후 처리 (`hwp_convert.py`)
- 자세한 사용법: `배포판/HWPX_Redactor/사용법.txt`
- 코드 수정 후 exe 재생성: `build_exe.bat`


중대재해조사보고서 HWPX를 토큰 소모 없이 로컬에서 비식별 처리합니다.

## ⭐⭐ 무인 자동화: 폴더 감시 (가장 편함)

`시작_폴더감시.bat` **더블클릭** → 창이 뜨면 그대로 두세요.
이제 `input` 폴더에 한글(.hwpx 또는 .hwp)을 **넣기만** 하면 자동으로:
- `output/` 에 `..._공개본.hwpx` 생성
- `done/` 에 원본 보관
- 자동탐지 경고·오류 문서는 `review/` 로 격리 + `log.txt` 기록 (조용한 누락 없음)

명령으로 켜려면: `python watch_redact.py` (종료 Ctrl+C)

**PC 켤 때 자동 시작**(선택): 작업 스케줄러 → 새 작업 → 트리거 "로그온할 때" →
동작 "프로그램 시작"에 `시작_폴더감시.bat` 지정.

> 완전 오프라인입니다 — 파일이 PC 밖으로 나가지 않아 중대재해 개인정보 처리에 안전.

## ⭐ 수동 실행: 완전 자동 (YAML 불필요)

```
python redact_auto.py 원본.hwpx
python redact_auto.py *.hwpx          # 여러 개 한꺼번에
```

재해사업장 개요표·재해자표·조사자표가 **고정 포맷**인 점을 이용해
이름·회사명·번호를 표에서 자동으로 읽어 처리합니다. 설정 입력이 전혀 없습니다.

자동 처리 항목:
- 재해자명 → 재해자A, B, C …
- 대표자 → 사업주A, B
- 조사자(공단 직원) → 공란 삭제
- 주민번호 → 출생년도
- 전화·팩스 삭제
- 소재지 → 시·구까지
- 산재·사업개시번호 삭제
- 직종 칼럼 비우기
- 회사명(원·하청) → 검색불가 이미지 대체 (본문 전체)
- 미리보기(PrvText/PrvImage) 정리
- 한컴 호환 in-place 재패키징 + 변환 후 잔재 자동 검수

결과물: `원본_공개본.hwpx`, 콘솔에 비식별 건수와 잔재(0) 리포트 출력.

## 설치 (최초 1회)

```
pip install pillow
```
- Python 3.8+ 와 **Pillow 하나만** 있으면 됩니다 (나머지는 파이썬 표준 라이브러리).
- 한글 폰트는 Windows 기본 **맑은 고딕** 자동 사용 → 폰트 설치 불필요.
- numpy·pyyaml **불필요** (config.yaml 방식을 쓸 때만 `pip install pyyaml` 추가).

## 작업 PC로 가져가서 쓰는 법

1. `redact_auto.py` 와 `redact_hwpx.py` **두 파일을 같은 폴더**에 둡니다.
2. 변환할 `.hwpx`를 같은 폴더에 넣습니다(다른 폴더면 경로로 지정해도 됨).
3. 그 폴더에서:
   ```
   python redact_auto.py 파일명.hwpx
   ```
4. 같은 폴더에 `파일명_공개본.hwpx` 가 생성됩니다.

> redact_auto.py가 redact_hwpx.py를 부품으로 불러 쓰므로 **반드시 둘이 같은 폴더**에 있어야 합니다.

## 수동 버전 (예외 문서용): redact_hwpx.py + config.yaml

표 구조가 특이해서 자동 탐지가 빗나가는 문서는 `config.example.yaml`을 `config.yaml`로 복사해 이름/회사명을
직접 적고 `python redact_hwpx.py config.yaml` 로 처리하세요.


## 서식이 작성자마다 다른 문제 (중요)

이 도구는 위치를 박아두지 않고 **라벨(칸 제목)을 이정표로** 값을 찾으므로,
칸 순서·줄 위치가 달라져도 견딥니다. 추가로:
- **라벨 동의어** 인식: 성명/이름, 소재지/주소, 대표자/대표이사, 전화번호/연락처,
  산재관리번호/사업자등록번호/사업개시번호, 직종/담당업무 등.
- **값 위치 양방향**: 값이 라벨 오른쪽이든 아래 칸이든 모두 탐색.
- **주민번호·전화번호는 서식과 무관**하게 정규식으로 항상 처리.

그래도 한계는 있습니다 → **자가진단 경고**로 알려줍니다:
실행 후 콘솔에 `검출: 재해자 N / 사업주 N / 조사자 N / 개요표 N개`가 찍히고,
표를 못 찾으면 `⚠️ 자동탐지 점검 필요` 경고가 뜹니다.
**경고가 뜨거나 검출 수가 이상하면 그 문서만 육안확인 또는 Cowork로** 처리하세요.
(조용히 누락되는 게 아니라, 못 찾으면 반드시 알려주는 구조입니다.)

## 한계 (사람 확인 권장)

- 표 레이아웃이 표준과 다르면 자동 탐지가 빗나갈 수 있음 → 결과 콘솔 리포트·문서 육안 확인.
- 붙임 사진·그림 속 로고·간판 등 **이미지에 박힌 식별정보는 처리 못 함** → 별도 확인.
- 회사명 영문 약칭(예: ABC)은 단어경계로만 매칭(오·과매칭 방지). 특이 약칭은 결과 확인 권장.

## 한컴 "변조 가능성" 경고가 뜨면

원본 zip 최소변경(in-place) 방식이라 대개 정상이나, 그래도 뜨면:
한글 **도구 > 환경설정 > 보안 > 문서 보안 설정을 '낮음'** 후 열기
→ 한 번 열어 다른 이름으로 저장하면 네이티브 정상 파일로 정착.

## 저장소 관리 주의 (개인정보)

`.gitignore`는 **허용목록 방식**입니다 — 소스코드만 커밋되고 `.hwp/.hwpx`, `log.txt`, `config.yaml`,
`input/ output/ done/ review/`, exe·DLL은 절대 올라가지 않습니다. 새 소스파일을 추가하면 `.gitignore`에 `!파일명`을 추가하세요.
실제 문서의 이름·회사명을 코드 주석이나 예시에 쓰지 마세요.
